# 3. The interview process

## The official process

1. **Application** with a 1–1.5 minute video (done).
2. **Intro call** (~30 min) with the Talent team. Yours: **Fri 27 Nov 2026, 4 pm IST, with Jakub
   Ossowski**. An AI notetaker records it.
3. **Technical take-home** (~8–10 hours of work, 7 days to submit).
4. **~90 min interview including live coding** with the Head of GTM.
5. **Final interview** with a co-founder and the Head of GTM.

## What candidates have reported (for other roles at the company)

About 14 public candidate reviews exist across engineering and business roles; none yet for this
exact role.

- **Difficulty:** rated "average".
- **Live round format (engineering):** a shared codebase with bugs and bug reports. Find the cause,
  fix it, implement a feature end to end. "Real world problem scenarios", not puzzles. One SQL
  question: select rows where a value is above X.
- **Tech challenge:** a take-home before interviews; one backend candidate's included SQL and test
  cases.
- **Final:** a culture-fit conversation with the CEO, behavioural questions.
- **Common complaints:** slow replies and vague rejections. A rejection without a reason is normal
  here and says little about you.

## What GTM-engineer interviewers reward everywhere

- **Working code over elegant code.**
- Handling **messy data and unexpected API formats** without crashing.
- Explaining technical work in **business terms**.
- **Specific answers with numbers.**

## What you can skip entirely

LeetCode-style algorithms, machine learning, advanced object-oriented design, async programming,
web frameworks beyond one tiny Flask app, database administration.

## The one rule

Everything you say you built must be something you built and can explain. If AI writes code for
you, read every line until you could rewrite it yourself. The live round asks you to change your
own code.
